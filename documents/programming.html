Getting started

  1. Read the repository README and inspect the existing Kotlin modules.
  2. Pick a small issue or improvement.
  3. Fork, create a feature branch, and make a focused change.
  4. Build and test on the relevant platform.
  5. Open a Pull Request explaining the change.

Best practices

  • Prefer val over var where possible.
  • Use descriptive names and small functions.
  • Handle nullable data safely; avoid !!.
  • Do not block the UI thread with I/O.
  • Follow existing project architecture and formatting.

Kotlin examples

1. Data class and safe validation

data class ConversionRequest(val inputPath: String, val outputPath: String)

fun validateRequest(request: ConversionRequest): String? {
    if (request.inputPath.isBlank()) return "Input path is required"
    if (request.outputPath.isBlank()) return "Output path is required"
    if (request.inputPath == request.outputPath) return "Paths must differ"
    return null
}

2. Result-based error handling

fun parseExtension(filename: String): Result<String> = runCatching {
    require('.' in filename) { "Missing file extension" }
    filename.substringAfterLast('.').lowercase()
}

3. State for a Compose interface

@Composable
fun ConversionStatus(message: String) {
    Text(text = message)
}

These are illustrative Kotlin snippets, not verified V-Converter APIs. The Compose snippet assumes Compose dependencies and imports are available.

4. Kotlin coroutines (conceptual example)

suspend fun loadText(readText: suspend () -> String): Result<String> =
    runCatching { readText() }

Kotlin tips

Keep platform-specific APIs behind interfaces when sharing code across targets. Validate file paths, report useful errors, and test unusual input.

Before your Pull Request

  • Check the project build instructions.
  • Test success and failure paths.
  • Remove debug code and unrelated changes.
  • Describe affected platforms and attach screenshots when UI changes.
